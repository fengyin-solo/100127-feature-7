# 冷链物流运输管理平台

面向冷链运输全程温控、车辆调度、门到门配送、温度异常处置、签收回单与运力结算的冷链运输管理后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 运输路线里程口径

运输路线的预计里程、预计耗时、过路费用不再由调度员手填，统一按口径自动取数，规则集中在
`backend/app/services/route_rules.py`（纯标准库，可独立测试），业务流转在 `services/route.py`。

- **预计里程**：按「出发地 → 有序途经节点 → 目的地」逐段标准里程相加。
- **预计耗时**：里程 ÷ 车型类别平均时速（小型/中型/重型）+ 固定休整预留，同时给出「X小时Y分钟」。
- **过路费用**：按车型类别费率与里程分档（阈值内基础单价、超出长途单价）给参考值。
- **里程偏离**：预计里程超过「出发地直达目的地里程 × 上限倍数」时标记「偏离」并写明数值与绕行原因。
- **同编号多节点**：同一「路线编号」可挂多套途经节点，用「路线指纹」（起讫点 + 有序节点）区分；
  节点顺序不同即不同方案，里程/耗时分别计算。
- **节点异常**：途经节点缺失、只有分隔符、节点不在路网里程库、相邻节点缺里程时，**不生成参考值**
  并逐条说明原因。
- **规则版本化**：`RULE_VERSIONS` 只增不改，录入结果带版本号；规则改动后通过
  `POST /api/route/rules/activate` 发布新版本，再 `POST /api/route/recalculate` 把既有记录
  整体重新算一遍。
- **复核一致性**：录入那一刻的计算依据（版本、节点链、分段里程、时速、过路费规则等）被原样
  冻结为 `frozen_basis`；重算结果单列 `recalc_*`，**不覆盖**录入依据。复核人在「里程依据」
  弹窗看到的永远是录入时那份；确认新口径后点「重新定基」，旧依据进入「口径变更历史」留痕。
- **登记前试算**：`POST /api/route/preview` 不落库，即时预览口径结果与偏离提示。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
